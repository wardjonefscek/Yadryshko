## Решения

| Что | Решение | Почему |
| --- | --- | --- |
| Язык | только Rust; Python в проекте не используется | решение 30.10.2026 |
| Сторонние CAD-ядра | не используем, OpenCASCADE исключён | своё ядро |
| Внешние библиотеки | нет ни в ядре, ни в тестах | сборка без интернета; в среде Claude crates.io закрыт |
| unsafe-код | запрещён во всём проекте | ошибки памяти исключены на уровне компилятора |
| Единицы | мм; 2D — целые микрометры (i64), предел ±2^40 мкм | 2D-предикаты точны в i128 |
| 3D | f64; предикаты — фильтр Шевчука и своя длинная арифметика | точный знак без всяких допусков |
| Случайные тесты | свой testkit вместо proptest: SplitMix64, сид на каждый случай | без внешних библиотек |
| Эталон точной арифметики | целые i128 и сверка по модулю двух простых чисел | эталон не зависит от нашей длинной арифметики |
| Версия Rust | закреплена: 1.97.0 в rust-toolchain.toml | формат и clippy одинаковы у всех; обновлять осознанно |
| Стенд | `cargo xtask` на Rust, без зависимостей | одинаково на Windows и Linux; собирается, даже когда ядро сломано |
| Сиды | днём постоянный, ночью новый на каждый раунд | днём прогоны повторяются, ночью ищут новые случаи |
| 2D-булевы | snap rounding (Хобби) на сетке 1 мкм: точки пересечений округляются в «горячие пиксели», рёбра проходят через их центры | результат снова на сетке и без пересечений; сдвиг не больше 0,71 мкм |
| Правило заливки | ненулевая обмотка; любая операция — правило `(в A, в B) → в результате` | одна процедура на все операции и на нормализацию входа |
| Корректная область | контуры не пересекаются и не накладываются, касание в точке можно; слева от ребра обмотка 1, справа 0; внешние против часовой, отверстия по часовой | проверяет `Region::check`; результаты операций корректны всегда |
| Обмотка у ребра | луч вправо из середины ребра, сдвинутой на символический ε влево | без особых случаев «луч через вершину» |
| Самопересекающийся контур | допустим во входе (`Ring`); нулевая ориентированная площадь — не ошибка | «бантик» по ненулевой обмотке закрашен |
| Обмотки граней | один луч на связную компоненту, остальное — обход граней (через ребро обмотка меняется на его вклад) | O(E log E) вместо O(E²); старый луч на каждое ребро остался эталоном в тестах |
| Дуги | строительная геометрия в мм (`Arc`, `Path` с bulge как в DXF); в булевы операции идут ломаной с вершинами на окружности, прогиб хорды ≤ допуска (по умолчанию 2 мкм) | точные дуго-дуговые пересечения на сетке не нужны; площадь и длина `Path` считаются по настоящим дугам |
| Эквидистанта | сумма Минковского через одну булеву операцию: область ∪ полосы рёбер ∪ сектора выпуклых вершин (внутрь — вычитание) | корректность по построению; схлопывание отверстий и разрывы перемычек — сами собой |
| Точность эквидистанты | граница на |d| − tol − 1,42 мкм … |d| + 1,42 мкм от исходной | углы кусочков и snap rounding — по 0,71 мкм; хорды внутри дуг |
| Профиль из .dat | Selig и Lednicer определяются сами; файл в долях хорды (носок и кромка не дальше 0,001 от (0, 0) и (1, 0)) берётся как есть, иначе приводится к хорде 1 по точке, самой далёкой от середины кромки | файлы UIUC не меняются; повёрнутый и в мм приводятся одинаково при любом повороте |
| Задняя кромка | `with_min_te_gap` — недостающее добавляется линейно по x, половина вверх, половина вниз | кромка тоньше сопла или фрезы не изготовится |
| Контур из плотности | marching squares по центрам элементов; седла — по седловой точке билинейной интерполяции; уплотнение Catmull-Rom; за краем поле повторяет край, результат обрезается областью | каждый отсчёт ≥ порога внутри, ниже — снаружи; края области точные |
| Мелочь после TopOpt | `Region::drop_small`: острова уходят со своими дырами, дыры заполняются вместе с островами в них | шум оптимизации; вложенность важна — иначе дыра убранного острова становится соринкой |
| Восстановление дуг | жадно: от каждой вершины — самый длинный отрезок или дуга в допуске (по умолчанию 5 мкм); дуга не больше π + 0,1; целая окружность — две полуокружности (в DXF — CIRCLE); вершины касаний остаются | Хаусдорф ≤ допуска доказуемо проверкой вершин и рёбер (обоснование в fit.rs) |
| DXF | запись R12 (POLYLINE с bulge, CIRCLE, слои); чтение POLYLINE, LWPOLYLINE, CIRCLE, LINE и ARC со сцепкой концов до 1 мкм | R12 читают все CAM, лазеры и станки |
| SVG для станка | в мм (1 единица = 1 мм), Y перевёрнута, дуги командой A, радиус с 9 знаками | середина дуги около полуокружности чувствительна к радиусу (√(2·R·δR)) |
| Область из листа | чёт-нечет по контурам | так понимают вложенные контуры CAM: окружность в детали — отверстие |
| Карточка ошибки | при падении случайной проверки пример ужимается (контуры, вершины, вдвое меньше, короче числа), карточка HTML в target/cards: текст, команда повтора, картинка, код для каталога | найденная ошибка сразу становится тестом; проверено подсаженной ошибкой (30 вершин → 6) |
| Фреза | `closing(r)` — что оставит фреза радиуса r (внутренние углы с радиусом r, узкие пазы не прорезаны); `opening(r)` — скругление выпуклых углов | обычная морфология, две эквидистанты |

## Правила работы

1. Сначала ЖУРНАЛ.md и КАРТА.md, потом только нужные модули.
2. После каждой правки — `cargo xtask check` (секунды). Перед выпуском
   версии — `cargo xtask check --full`. Ночью — `cargo xtask night 7`,
   утром — отчёт из `reports/`.
3. Найденная ошибка сначала становится тестом, потом чинится.
4. Хрупкие места помечены `РИСК:`: менять их только вместе с тестами.
5. Упавший случай печатает команду повтора:
   `YADRO_SEED=… YADRO_CASES=1 cargo test -p yadro-core <тест>`.
6. Код и объёмную работу Claude начинает только после отдельного «да».
7. Для Claude: в его среде нет интернета для rustup. Если там установлен
   только stable той же версии, сделать её доступной под закреплённым
   именем: `ln -s stable-x86_64-unknown-linux-gnu
   ~/.rustup/toolchains/1.97.0-x86_64-unknown-linux-gnu` (из папки
   ~/.rustup/toolchains). Если версия другая — `RUSTUP_TOOLCHAIN=stable`
   и предупредить, что замечания clippy могут отличаться.

## Отложено на следующие ступени

- Карточка ошибки для 3D (просмотр в браузере) — ступень 2.
- Поиск пар рёбер с пересекающимися габаритами — сортировкой по x; для
  контуров TopOpt из десятков тысяч рёбер может понадобиться настоящая
  заметающая прямая (шаг 4, по замерам).
- Восстановление дуг жадное: короткую прямую между скруглениями может
  забрать дуга большого радиуса (в допуске). Если понадобятся «красивые»
  разбиения — разбиение с наименьшим числом участков.
- cargo-fuzz, cargo-mutants, cargo-llvm-cov ставятся как инструменты на ПК
  или сервер; в сам проект они не входят.

  ломаная → отрезки и дуги с допуском, целые окружности, вершины касаний на
  месте. Лист (`Sheet`): контуры по слоям, область с восстановлением дуг,
  габарит по настоящим дугам, DXF R12 и SVG в мм; чтение DXF (`dxf`):
  POLYLINE, LWPOLYLINE, CIRCLE, LINE и ARC вразброс со сцепкой, ошибки с
  номером строки; область из листа по чёт-нечет. Карточка ошибки (`card`):
  ужатие примера, страница HTML с командой повтора, картинкой и кодом для
  каталога; в testkit — `quietly`, `shrink`, `replay_command`; подключено к
  случайным тестам булевых операций и эквидистанты. Ворота: окружности,
  скругления, пазы и углы эквидистанты — дугами с верными радиусами;
  контур из плотности ужимается в 5+ раз; DXF и SVG читаются обратно в то
  же самое (SVG — своим разбором в тесте); DXF «чужих программ»;
  подсаженная ошибка даёт карточку с парой треугольников; 100 000
  случайных областей — Хаусдорф в допуске, ориентация сохранена. Найдено
  случайными проверками и исправлено: дуга около полуокружности в SVG
  уходила на доли микрона от округления чисел — теперь пишется кусками не
  больше четверти окружности; подгонка схлопывала щепки тоньше допуска в
  пустой контур — теперь такие остаются ломаной (случай в каталоге);
  проверки площади и точности DXF были строже самого формата (6 знаков).
  Пример topopt_rib пишет DXF и SVG для станка (1847 вершин → 494
  участка, из них 211 дуг). Тестов: 156 в ядре и 3 в стенде; полный
  прогон — 11 мин 35 с (из них 7 мин — 100 000 случайных экспортов).
- **0.1.5** — 05.11.2026 — ступень 1, шаг 4. Профили (`Airfoil`): чтение
  .dat Selig и Lednicer (комментарии, CRLF, запятые, экспонента с D, повторы
  точек), приведение к хорде 1, верх/низ, толщина, средняя линия, NACA
  4-й серии, утолщение задней кромки, размещение с хордой, круткой и точкой
  поворота, запись Selig. Поле плотности (`DensityField`): контур по
  порогу marching squares с седлами по билинейной интерполяции, уплотнение
  Catmull-Rom, точные края области; `Region::drop_small` с учётом
  вложенности. Ворота: Clark Y из базы UIUC (11,7% толщины), Selig и
  Lednicer совпадают, повёрнутый файл приводится одинаково, ошибки с номером
  строки, площадь NACA по интегралу формулы; поле из единиц — ровно
  область, линейное — ровно полуплоскость, один элемент — ромб 0,5 мм²,
  седла, вложенные острова и дыры, уплотнение скругляет окружность вдвое
  точнее; случайные поля — каждый отсчёт классифицирован верно. Найдено и
  записано в тесты: дыра внутри убранного острова превращалась в соринку;
  порог площади сравнивался после округления вниз. Пример topopt_rib:
  нервюра Clark Y с облегчением по полю плотности. Тестов: 134 в ядре и 3

- **0.1.4** — 05.11.2026 — ступень 1, шаг 3. Дуги (`Arc`): по bulge, по

  закрывается, щель сливается, перемычка рвётся, L-деталь, острие 1°,

  своём расстоянии, пробы внутри и снаружи совпадают с расстоянием,
